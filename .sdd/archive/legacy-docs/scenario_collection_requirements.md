# 未知勒索、未知后门和数据窃取场景：补充数据采集诉求

> 适用范围：Linux 主机、Linux 容器和 Kubernetes Linux 节点  
> 文档用途：项目立项、现有数据盘点、采集侧需求沟通和端到端方案设计  
> 不包含：Agent 通用底层基座、RAG/MCP 平台实现、Windows 取证

## 1. 目标

现有 CDE 引擎以静态文件检测为核心，现有产品链路还会输出一部分文件、进程链、异常事件、网络字段、用户、资产和容器上下文。

本项目不重复实现 CDE 检测，而是补足未知文件案件所需的运行时证据，使威胁研判 Agent 能够：

- 跨文件：关联未知文件与其来源文件、释放文件、脚本、配置和后续产物。
- 跨时间：向前追溯落地、登录和潜伏，向后追踪执行、外联、窃取、持久化和破坏，并查询历史重复行为。
- 跨主机：沿相同文件、IOC、账号、密钥、连接、容器镜像和共享存储扩展调查。
- 覆盖未知勒索、未知劫持后门/远控和未知数据窃取三个场景。
- 输出可引用原始证据的行为路径、攻击路径、反证和案件结论。

本文所说“补充采集”包括两种情况：

1. 当前完全没有，需要新增传感器或日志配置。
2. 当前已经产生，但没有保存足够字段、保留时间或查询能力，需要增强。

## 2. 三层数据需求总览

采集诉求按照终端系统层、网络传输层、静态与二进制结构层组织。三个攻击场景不是独立的数据层，而是使用三层数据进行综合研判的业务视角。

```text
静态与二进制结构层
回答：未知文件是什么，静态上可能具备什么能力？
        ↓ 产生 Hash、路径、字符串、命令、IOC 和行为线索

终端系统层
回答：未知文件在真实主机上是否执行，具体做了什么？
        ↓ 产生进程、文件、账号、服务、持久化和影响证据

网络传输层
回答：相关进程与谁通信，是否形成 C2、外传或跨主机活动？
        ↓ 产生连接、DNS、流量、协议和跨资产证据

三层证据关联
        ↓
跨文件 + 跨时间 + 跨主机
        ↓
后门 / 数据窃取 / 勒索案件研判
```

### 2.1 终端系统层

#### 2.1.1 目标

终端系统层负责证明未知文件在真实 Linux 主机或容器中发生的运行时行为：

- 文件如何进入主机。
- 文件是否真正执行。
- 谁执行、由什么父进程和会话触发。
- 执行后创建、读取、修改或删除了什么。
- 是否修改账号、权限、服务和持久化配置。
- 是否访问敏感数据。
- 是否批量加密或破坏文件与恢复能力。
- 是否通过凭据、远程会话或共享存储影响其他主机。

静态文件中的可疑字符串只能作为终端调查线索，不能代替真实运行时证据。

#### 2.1.2 数据类别

| 数据类别 | 关键事件或对象 | 主要用途 |
| --- | --- | --- |
| 主机身份 | host ID、machine ID、Boot ID、资产角色、时区 | 跨时间、跨主机和重启边界 |
| 进程执行 | fork/clone/exec、父子进程、命令行、工作目录、用户 | 证明执行并重建进程链 |
| 文件运行时 | create、read、write、rename、chmod、delete、execute | 证明落地、数据访问、勒索和清理 |
| 认证与会话 | SSH、PAM、sudo、su、TTY、来源 IP | 追溯入口、账号和跨主机访问 |
| 用户与权限 | 用户、组、sudoers、SSH key、SUID/SGID、capability | 后门、提权和凭据滥用 |
| 服务与任务 | systemd、cron、at、SysV、`rc.local` | 后门持久化和勒索服务破坏 |
| 系统配置 | 动态链接器、内核模块、挂载、启动和恢复配置 | 劫持、隐藏、持久化和恢复阻断 |
| 存储与备份 | LVM、Btrfs、ZFS、备份、快照、共享存储 | 勒索破坏范围和恢复能力 |
| 容器运行时 | 容器、Pod、镜像、宿主 PID、挂载、exec | 容器内行为及宿主关联 |
| 应用与业务 | Web、数据库、发布、备份和运维任务 | 入口分析及合法反证 |
| 资源与行为聚合 | 文件操作速率、磁盘 I/O、CPU、影响目录数 | 发现批量勒索和大规模收集 |

#### 2.1.3 三个场景的终端重点

| 场景 | 终端系统层重点 |
| --- | --- |
| 未知勒索 | 高频文件改写、统一重命名、文件内容变化、服务停止、备份/快照删除、勒索信、共享存储影响 |
| 未知后门 | 隐藏/伪装进程、删除后运行、进程劫持、账号和SSH key、cron/systemd、监听与连接主体 |
| 数据窃取 | 敏感目录读取、数据库导出、凭据访问、归档压缩、暂存文件、跨主机登录 |

#### 2.1.4 终端层核心字段

```text
event_id
event_time
host_id
machine_id
boot_id
container_id / pod_uid
process_entity_id
parent_process_entity_id
pid / ppid / process_start_time
executable_path / executable_hash
cmdline / argv / cwd
uid / euid / session_id
operation
object_path
old_value / new_value
result
raw_reference
```

### 2.2 网络传输层

#### 2.2.1 目标

网络传输层负责证明：

- 未知文件对应进程是否建立网络连接或监听端口。
- 是否存在反向连接、周期回连、代理、隧道或 WebShell 通信。
- 是否向外部传输数据，传输量和时间是否与数据归集行为吻合。
- 是否连接、登录或控制其他内部主机。
- 相同 IP、域名、DNS、TLS 或流量模式是否出现在其他主机和历史时间。

网络事件必须尽可能绑定终端进程。只有 IP 和端口而没有进程归属时，只能作为关联线索，不能单独证明由未知文件产生。

#### 2.2.2 数据类别

| 数据类别 | 关键内容 | 主要用途 |
| --- | --- | --- |
| 主机连接 | connect、accept、listen、close、进程实体 | C2、反连、监听和外传主体 |
| DNS | 查询名、类型、答案、进程、频率和长度 | 域名关联及DNS隧道 |
| 流量统计 | 五元组、方向、持续时间、收发字节 | 外传规模和周期通信 |
| HTTP/HTTPS | Host、方法、路径、方向、状态、TLS元数据 | WebShell、下载和上传 |
| 代理 | 用户、主机、目标、请求、上传字节 | 数据外传和合法业务识别 |
| 防火墙/IDS/IPS | 连接、阻断、告警和原始会话 | 网络侧交叉印证 |
| WAF/Web日志 | 来源IP、URL、请求时间、服务实例 | Web入口、上传和命令执行 |
| SSH/SCP/SFTP | 来源、目标、用户、会话、流量 | 跨主机和数据传输 |
| NetFlow | 跨主机五元组和流量 | 大范围历史检索 |
| PCAP | 按需的协议和内容证据 | P2增强，不作为一期前提 |
| 云/对象存储 | API主体、对象、操作、字节数 | 云端数据外传 |

#### 2.2.3 三个场景的网络重点

| 场景 | 网络传输层重点 |
| --- | --- |
| 未知勒索 | 载荷下载、横向分发、控制指令、加密前外传、多主机同步活动 |
| 未知后门 | 反向连接、监听、周期回连、DNS隧道、WebShell、代理和端口转发 |
| 数据窃取 | 大量异常出站、HTTPS上传、SCP/SFTP、DNS外传、云存储和目标信誉 |

#### 2.2.4 网络层核心字段

```text

start_time / end_time
host_id / container_id
process_entity_id
network_namespace
protocol
src_ip / src_port
dst_ip / dst_port
direction
domain / dns_answer
http_host / method / path
tls_server_name / certificate_fingerprint
bytes_sent / bytes_received
connection_result
raw_reference
```

### 2.3 静态与二进制结构层

#### 2.3.1 目标

静态与二进制结构层负责：

- 确认文件真实类型、身份和基础属性。
- 理解 ELF 或脚本可能具备的能力。
- 提取命令、路径、URL、IP、域名、密钥标志、持久化对象等调查线索。
- 发现文件之间的释放、嵌入、下载或配置引用关系。
- 将静态线索提供给终端和网络层进行现场验证。

该层优先消费 CDE 和现有算法输出，不重复建设一套静态恶意文件检测系统。补充诉求主要是“开放现有结果、保留证据引用、补充结构化输出”，而不是重新检测黑白灰。

#### 2.3.2 文件通用数据

```text
sha256 / md5
file_path
real_file_type
size
mode
owner / uid / gid
create / modify / access / discovery time
package_ownership
signature
sample_reference
parent_archive / extracted_children
raw_reference
```

#### 2.3.3 ELF结构数据

建议开放或结构化输出：

- ELF Class、架构、字节序和入口点。
- Program Header、Section Header 和异常段/节。
- 动态链接器、依赖库、导入和导出符号。
- 是否 stripped、静态链接、PIE。
- 可疑字符串、路径、命令、IP、域名和URL。
- 加壳、混淆、嵌入数据和异常熵等分析结果。
- capability、SUID/SGID 和运行权限。
- 能力判断对应的偏移、符号或原始证据引用。

静态结构只表示“可能具备能力”，不能证明现场发生了注入、加密、C2或外传。

#### 2.3.4 脚本和Web文件数据

建议开放或结构化输出：

- 语言、解释器、入口和编码。
- 混淆、压缩、加密和解码层。
- 命令执行和子进程创建。
- 下载、上传、解压、释放和执行。
- 文件读取、修改、删除和权限操作。
- 网络目标和协议线索。
- cron、systemd、SSH key等持久化意图。
- WebShell命令入口和参数来源。
- 数据收集、压缩和外传意图。
- 每项结论对应的行号、函数、片段或证据ID。

#### 2.3.5 三个场景的静态重点

| 场景 | 静态与二进制结构层重点 |
| --- | --- |
| 未知勒索 | 文件遍历、加密库、密钥处理、扩展名修改、服务停止、备份破坏和勒索文本线索 |
| 未知后门 | 网络通信、命令执行、持久化、进程伪装、动态加载、WebShell和代理线索 |
| 数据窃取 | 敏感路径、凭据访问、数据库导出、归档压缩、加密和上传线索 |

### 2.4 三层之间如何关联

静态层产生调查线索，终端层验证真实行为，网络层验证通信和传输：

```text
静态层发现某个 C2 域名
→ 网络层查询哪些主机和进程访问该域名
→ 终端层还原这些进程由哪些文件和会话启动

静态层发现批量加密和勒索信路径
→ 终端层查询实际文件改写、服务停止和勒索信创建
→ 网络层查询载荷下载、控制和加密前外传

终端层发现敏感数据被归档
→ 静态层分析归档脚本和目标路径
→ 网络层查询归档后的异常出站传输
```

最终证据强度通常为：

```text
静态能力线索
< 单层运行时事件
< 终端进程与网络/文件行为直接归属
< 三层证据形成时间和因果闭环
```

## 3. 当前已确认可用的初始数据

### 3.1 `T_FILE_DETAILS` 或等价 JSON

当前已知包含：

- 文件 Hash、路径、类型、大小和权限。
- 文件创建、修改、访问和发现时间。
- 文件属主、UID、GID。
- 触发进程名、PID、PPID、UID、EUID 和进程创建时间。
- `DETAIL` 回溯进程链。
- 用户、访问 IP、登录账号。
- 主机、资产、Pod 和容器标识。
- 落盘或进程启动类型。
- HOFS 样本引用。

作用：

- 作为 Agent 的案件入口。
- 定位未知文件、当前主机和初始时间。
- 提供初步父子进程、用户和容器线索。

不足：

- 文件时间戳通常不能说明“哪个进程执行了哪次写入”。
- 不能默认提供完整文件读写、重命名、删除事件流。
- `DETAIL` 是否完整、顺序和回溯范围仍需确认。
- 当前记录不一定覆盖文件执行后的全部子进程和网络行为。
- 当前记录不一定支持历史和跨主机连续查询。

### 3.2 `T_PROCESS_CHAIN_HASH` 或等价 JSON

当前已知包含：

- 进程链文件 Hash。
- Hash 信誉类型。
- PID 和进程名。

作用：

- 为进程链节点补充文件身份和已有信誉。
- 发现进程链中的其他未知、灰色、可疑或恶意文件。

不足：

- PID 可能重用。
- 只有 PID 和进程名时，无法稳定区分不同时间的进程实例。
- Hash 信誉不是实际运行行为证据。

### 3.3 `T_abnormal_event_TO_REPORT_OS` 或等价 JSON

当前已知包含：

- 异常事件 ID。
- 文件和进程上下文。
- 源/目的 IP、攻击相关 IP、端口。
- 发生、检测、最近和上报时间。
- 攻击阶段、状态、置信度、次数和持续时间。
- 用户、登录、主机、Pod 和扩展信息。

作用：

- 提供现有算法已经发现的异常事件。
- 为网络、用户和攻击阶段提供初始调查线索。

不足：

- 聚合告警不能替代原始运行时事件。
- IP/端口字段不一定能归因到未知文件对应进程。
- 上游置信度不能直接成为最终案件置信度。
- 需要确认能否取得告警对应的原始记录。

## 4. 所有场景共同需要的 P0 数据

### 4.1 稳定的主机、进程和容器身份

必须采集或生成：

```text
host_id
machine_id
boot_id
process_entity_id
pid
ppid
process_start_time
container_id
pod_uid
namespace
image_digest
```

最低关联要求：

```text
主机 + Boot ID + PID + 进程启动时间
```

原因：

- 单独使用 PID 会受 PID 重用影响。
- 跨时间分析需要区分重启前后的进程。
- 容器 PID 与宿主 PID 需要映射。
- 跨主机检索必须有稳定资产身份。

### 4.2 进程创建和执行事件

每次执行至少采集：

```text
event_id
event_time
host_id / container_id
process_entity_id
parent_process_entity_id
pid / ppid
executable_path
executable_hash
argv / cmdline
cwd
uid / euid / gid / egid
session_id
tty
namespace
exit_status（可用时）
raw_reference
```

主要用途：

- 证明未知文件是否真正执行。
- 还原父进程、祖先进程和子进程。
- 识别 Web、SSH、cron、systemd 或容器触发来源。
- 将文件、网络和权限行为绑定到同一进程实体。

可能来源：

- auditd。
- eBPF/EDR/HIDS。
- 终端 Agent 进程事件。
- journald 和服务日志作为补充。

### 4.3 文件运行时事件

至少采集：

```text
create
open/read（重点目录或风险进程）
write
truncate
rename
chmod
chown
delete/unlink
execute
memory_map/load（能力允许时）
```

每条事件至少包含：

```text
event_id
event_time
host_id / container_id
process_entity_id
user_id
operation
path
old_path / new_path
inode + device（可用时）
file_hash（创建后或内容稳定时）
size_before / size_after
mode_before / mode_after
result
raw_reference
```

主要用途：

- 证明文件由谁创建、修改、执行和删除。
- 关联脚本释放 ELF、文件重命名和删除后运行。
- 发现勒索批量文件改写。
- 发现窃取场景的大量敏感文件读取。

### 4.4 带进程归属的网络事件

至少采集：

```text
connect
accept/listen
dns_query
connection_close
bytes_sent / bytes_received
```

每条事件至少包含：

```text
event_id
start_time / end_time
host_id / container_id
process_entity_id（关键）
protocol
src_ip / src_port
dst_ip / dst_port
direction
domain
dns_answer
bytes_sent / bytes_received
connection_result
network_namespace
raw_reference
```

主要用途：

- 证明网络连接是否由未知文件产生。
- 识别 C2、反向连接、监听和数据外传。
- 沿相同 IP、域名、证书或通信特征扩展到其他主机。

如果只能提供五元组而没有进程实体，必须标记为“可时间关联但不可直接归因”。

### 4.5 认证、用户和权限事件

至少采集：

- SSH 登录成功和失败。
- PAM 会话开始和结束。
- sudo、su 和权限切换。
- 用户、组和密码状态变化。
- SSH key 和 `authorized_keys` 变化。
- sudoers 和认证配置变化。
- Linux capabilities、SUID/SGID 和关键权限变化。

关键字段：

```text
event_time
host_id
user / uid
target_user / target_uid
session_id
source_ip
auth_method
process_entity_id（可用时）
operation
result
changed_object
raw_reference
```

### 4.6 系统和服务事件

至少采集：

- systemd service/timer 创建、修改、启停和失败。
- cron、at、SysV、`rc.local` 和启动脚本变化。
- 主机启动、关闭和 Boot ID。
- 挂载、卸载和共享存储变化。
- 内核模块加载。
- 审计和安全产品停止、失败或配置变化。
- 数据库、备份、存储和业务关键服务启停。

### 4.7 数据覆盖和采集健康

每次查询必须能返回：

```text
source
host_scope
time_range
collection_enabled
coverage_start / coverage_end
event_loss
truncation
delay
retention
query_limit
```

原因：

- “没有查到”可能是行为没发生，也可能是没有采集。
- Verdict 必须区分 `not_observed`、`not_collected` 和 `not_available`。

## 5. 跨文件分析的补充数据

需要支持从一个未知文件跳转到：

- 创建它的进程和源文件。
- 调用它的脚本、解释器和命令。
- 它释放、下载、复制、重命名或修改的其他文件。
- 它写入的持久化配置。
- 它读取或归档的敏感文件。
- 它产生的勒索信、压缩包和临时文件。

建议建立可查询关系：

```text
file -> created_by -> process
process -> executed -> file
process -> read/wrote/renamed/deleted -> file
script -> downloaded/released -> file
config -> references -> file
archive -> contains -> file
```

关键采集要求：

- 保留操作前后路径，支持 rename 链。
- 对新建可执行文件和脚本及时计算 Hash。
- 保留 inode/device，辅助识别改名后的同一文件。
- 对压缩包和释放文件保留父子关系。
- 保留 HOFS 或其他安全样本引用。

## 6. 跨时间分析的补充数据

Agent 需要从告警时刻向前和向后调查：

```text
向前：
首次出现 -> 创建/下载 -> 登录/入口 -> 更早潜伏

向后：
执行 -> 子进程 -> 外联 -> 持久化 -> 窃取/破坏

历史：
同文件/路径/命令/账号/IOC 是否重复出现
```

采集和存储诉求：

- 所有数据源统一时间基准并保留原始时区。
- 记录主机时钟偏移和 NTP 状态。
- 保留 Boot ID。
- 支持按文件 Hash、路径、进程、命令、账号、IP、域名和容器查询历史。
- 运行时明细建议至少覆盖案件调查周期；具体保留天数需结合数据量和业务确定。
- 长期层可以保留聚合关系、关键 IOC 和案件图，但不能用聚合数据替代近期原始证据。
- 支持周期性行为查询，例如同一小时、每日重复回连和定时执行。

## 7. 跨主机分析的补充数据

需要支持按以下对象跨主机检索：

- 相同 SHA-256、模糊 Hash、文件名和路径。
- 相同下载 URL、IP、域名、DNS 结果和通信目标。
- 相同账号、SSH key、API Token 标识或认证来源。
- 相同命令行、脚本片段和持久化配置。
- 相同容器镜像摘要、Pod 模板和挂载卷。
- 相同勒索扩展名、勒索信 Hash 或破坏模式。
- 同一共享存储上的关联操作。

每条跨主机结果必须保留：

```text
host_id
asset_role
event_time
matching_dimension
match_strength
source_event_id
raw_reference
```

仅共享一个常见 IP、命令或文件名通常属于弱关联，不能直接认定同一攻击。

## 8. 未知勒索场景的专项采集诉求

### 8.1 需要证明的问题

1. 未知文件是否真正执行。
2. 是否由该进程批量访问和修改文件。
3. 修改是否表现为加密、破坏或异常重命名。
4. 是否停止关键服务或破坏备份与恢复能力。
5. 是否影响挂载卷、共享存储、容器或其他主机。
6. 是否生成勒索信或其他勒索标志。
7. 是否存在合法加密、备份、发布或数据迁移解释。

### 8.2 P0 数据

#### 批量文件活动

除了原始文件事件，还需要按进程和时间窗口聚合：

```text
files_read_count
files_written_count
files_renamed_count
files_deleted_count
directories_affected
extensions_before / extensions_after
bytes_read / bytes_written
operation_rate
first_event_time / last_event_time
representative_raw_event_ids
```

建议采集原始事件并生成聚合视图，而不是只保存聚合结论。

#### 文件内容变化辅助指标

能力允许时采集：

- 修改前后大小。
- 修改前后 Hash 抽样。
- 文件头变化。
- 熵变化或内容随机性指标。
- 统一新增扩展名。

这些只能说明“疑似加密或重写”，必须和进程及批量行为结合。

#### 服务和恢复能力破坏

采集：

- 数据库、备份、存储、安全软件和业务服务停止事件。
- LVM、Btrfs、ZFS、云盘、虚拟化平台快照删除或修改。
- 备份目录、备份任务和保留策略变化。
- 挂载、卸载、只读/读写状态变化。
- 恢复配置和启动配置变化。

#### 勒索标志

采集：

- 多目录中新建的相同或相似文本/HTML 文件。
- 勒索信文件 Hash、路径、创建进程和时间。
- `/etc/motd`、登录提示、Web 页面等变化。

### 8.3 P1 数据

- 进程 CPU、磁盘 I/O 和文件操作速率。
- NAS、分布式存储和对象存储审计。
- 数据库异常关闭和损坏日志。
- 勒索发生前的数据归集和外传活动。

### 8.4 关键反证

- 正式变更单。
- 合法备份、加密、迁移和发布任务。
- 可信软件包及签名。
- 历史上相同账号、时间和命令的正常周期行为。
- 文件影响范围与预期任务范围一致。

## 9. 未知劫持后门/远控场景的专项采集诉求

### 9.1 需要证明的问题

1. 未知文件是否提供命令执行、远程控制或代理能力。
2. 是否建立反向连接、监听端口或周期回连。
3. 是否隐藏、伪装、注入或劫持正常进程。
4. 是否建立持久化。
5. 是否修改账号、密钥或权限。
6. 是否利用后门继续影响其他主机。
7. 是否可能是合法代理、监控、运维或远程管理程序。

### 9.2 P0 数据

#### 进程隐藏和伪装

采集：

- 进程名、可执行路径、命令行和实际文件 Hash。
- `/proc/<pid>/exe` 指向及“deleted”状态。
- argv、进程名和可执行路径不一致。
- 父进程、会话、TTY 和启动来源。
- 进程文件在执行后被删除或替换。

#### 劫持和注入相关事件

能力允许时采集：

- `ptrace` 目标进程和结果。
- `process_vm_writev` 等跨进程内存操作。
- 异常共享库加载。
- `/etc/ld.so.preload` 和动态链接器配置变化。
- 关键二进制或共享库替换。
- 内核模块加载和模块文件来源。

不能仅凭静态字符串认定已经完成进程注入。

#### 持久化

采集配置内容、变更前后值、操作者和实际触发事件：

- cron、at。
- systemd service/timer。
- SysV、`rc.local`。
- Shell profile。
- SSH `authorized_keys`。
- 用户、组和 sudoers。
- udev、内核模块和容器启动配置。

#### C2 和远程控制

采集：

- 带进程归属的连接、监听和 DNS。
- 连接周期、间隔、持续时间和字节数。
- DNS 请求长度、类型、频率和响应。
- WebShell 对应的 Web 请求、参数摘要、来源 IP 和服务进程。
- 代理、隧道和端口转发相关进程与连接。

### 9.3 P1 数据

- TLS 元数据和证书指纹。
- HTTP 方法、路径、Host、状态码和流量方向。
- NetFlow、代理、DNS 和防火墙的跨主机检索。
- 容器 exec、端口转发和 Kubernetes API 审计。

### 9.4 关键反证

- 合法远程运维、监控和代理软件清单。
- 软件包来源、发布记录和配置基线。
- 合法固定外联目标。
- 历史周期和资产角色一致。
- 持久化配置由可信部署系统创建。

## 10. 未知数据窃取/木马场景的专项采集诉求

### 10.1 需要证明的问题

1. 未知文件是否发现并访问敏感数据。
2. 是否复制、导出、归档、压缩或加密数据。
3. 是否生成暂存文件。
4. 是否产生与数据规模相符的异常外传。
5. 是否盗取账号、密钥或 Token 并访问其他主机。
6. 是否清理暂存文件或日志。
7. 是否可能是合法备份、同步、报表或数据交换。

### 10.2 P0 数据

#### 敏感对象访问

对重点对象采集 read/open 和目录遍历事件：

- 数据库文件和导出目录。
- 应用配置和密钥目录。
- SSH 私钥和 `authorized_keys`。
- API Token、云凭据、证书。
- 浏览器 Cookie、会话和密码存储。
- 源代码、业务文档和用户目录。
- 容器 Secret、ServiceAccount Token 和挂载凭据。

为了控制数据量，可采用：

- 重点目录和重点进程精细采集。
- 对高频读取生成聚合指标。
- 保留代表性原始事件。

不得采集或回传敏感文件明文作为默认行为；优先保存路径、类型、Hash、大小、访问主体和证据引用。

#### 数据归集和暂存

采集：

- 数据库导出进程和命令。
- 归档、压缩和加密进程。
- 新建大文件、压缩包和隐藏暂存文件。
- 输入文件集合与输出文件的关联。
- 暂存文件创建、读取、上传和删除时间。

#### 数据外传

采集：

- 带进程归属的出站连接。
- 发送/接收字节数。
- DNS、代理和防火墙事件。
- HTTP/HTTPS 上传方向和目标。
- SCP/SFTP/SSH 会话。
- 云存储和对象存储访问审计。
- 容器和 Pod 的出站连接。

确认“数据外传”至少需要：

```text
数据访问或归集证据
+ 暂存/传输主体关联
+ 异常出站传输证据
```

只有外部连接不能证明数据被窃取。

#### 凭据使用和跨主机访问

采集：

- SSH key、Token 和凭据文件访问。
- 随后的登录、API 调用和目标主机。
- 来源主机、账号、认证方式和会话。
- 失败后成功、异常时间和首次访问等历史特征。

### 10.3 P1 数据

- 数据库审计日志。
- DLP、代理、邮件、对象存储和云审计。
- `/dev/video*`、输入设备和桌面会话访问事件。
- 剪贴板、截图和录制产物的文件证据。
- 网络流量内容摘要或 PCAP（依法合规、按需使用）。

### 10.4 关键反证

- 合法备份、同步、报表、运维和数据交换任务。
- 可信进程和服务账号。
- 目标域名、云存储和流量规模符合业务基线。
- 有审批的数据库导出。
- 历史上相同时间和命令的周期任务。

## 11. 三类场景串联所需数据

三类攻击可能形成：

```text
初始落地
→ 后门/C2 与潜伏
→ 凭据访问和跨主机扩展
→ 敏感数据发现、归集和外传
→ 停止服务、破坏备份
→ 批量加密和勒索
```

要还原该链，必须能够把以下关系连接起来：

| 前一步 | 后一步 | 关键关联字段 |
| --- | --- | --- |
| 文件落地 | 文件执行 | 主机、路径/Hash、时间、创建进程、执行进程 |
| 文件执行 | C2 | 进程实体、网络命名空间、连接时间 |
| C2 | 持久化 | 进程实体、配置变更主体、目标文件 |
| 后门 | 凭据访问 | 进程实体、敏感文件、账号、会话 |
| 凭据访问 | 跨主机登录 | 凭据/账号标识、来源主机、目标主机、时间 |
| 登录 | 数据归集 | 会话、进程树、文件读取和导出 |
| 数据归集 | 外传 | 暂存文件、上传进程、目标、字节数、时间 |
| 外传 | 勒索部署 | 会话、文件分发、进程和主机集合 |
| 勒索部署 | 批量破坏 | 进程实体、文件事件聚合、服务/备份事件 |

## 12. 采集优先级

### P0：一期必须

- 稳定主机和进程身份。
- 进程创建和执行。
- 文件创建、写入、重命名、权限修改、删除和执行。
- 带进程归属的网络连接和 DNS。
- SSH、sudo、用户、密钥和权限变化。
- systemd、cron、服务启停和持久化配置变化。
- 批量文件活动聚合及代表性原始事件。
- 敏感目录访问和数据归集事件。
- 跨时间历史查询。
- 按 Hash、路径、账号、IP、域名跨主机查询。
- 数据覆盖、丢失和保留信息。

### P1：强烈建议

- Web/WAF、代理、防火墙、DNS、NetFlow。
- 数据库审计。
- LVM/Btrfs/ZFS/备份和存储平台审计。
- Kubernetes API 和容器 runtime 审计。
- TLS、HTTP 和流量方向元数据。
- CPU、磁盘 I/O 和操作速率。
- 软件包、发布、变更和业务基线。

### P2：条件增强

- PCAP。
- 内存取证。
- 完整系统调用序列。
- 沙箱动态报告。
- DLP 和内容级外传证明。
- 摄像头、输入设备和桌面会话专项遥测。

## 13. 向采集侧确认的问题

### 已有表

1. 三张表分别由哪些组件写入？
2. 字段是原始采集值、聚合结果还是算法推断？
3. `DETAIL.tree[]` 的顺序、最大深度和缺失条件是什么？
4. `REALTIME_TYPE=1` 能否证明执行，还是只表示扫描触发方式？
5. 网络 IP/端口是否能关联到目标进程实体？
6. 文件创建、修改、访问时间是文件元数据还是事件时间？
7. 三张表保留多久，能否按时间和主机进行历史查询？
8. 是否保留原始日志和原始事件引用？

### 新增运行时数据

9. 当前终端 Agent 是否采集进程执行事件？
10. 是否采集文件读写、重命名、删除和权限变化？
11. 是否采集连接、监听、DNS和进程归属？
12. 是否采集 SSH、sudo、账号和密钥变化？
13. 是否采集 systemd、cron、服务和备份变化？
14. 是否支持容器 PID 与宿主进程映射？
15. 是否存在跨主机历史检索平台？
16. 能否返回数据覆盖、丢失、截断和保留信息？

### 数据量和隐私

17. 高频文件读写如何聚合，同时保留代表性原始证据？
18. 敏感文件访问是否只返回元数据而不返回内容？
19. 网络数据可保留到什么粒度？
20. 跨主机查询的权限和范围如何控制？

## 14. 最低可行采集组合

如果一期无法实现全部采集，最低组合应为：

```text
现有三张表
+ 稳定进程执行事件
+ 文件创建/写入/重命名/删除事件
+ 带进程归属的网络连接
+ SSH/sudo/账号事件
+ systemd/cron/服务事件
+ 批量文件操作聚合
+ 敏感目录访问聚合
+ 跨时间和跨主机查询
+ 数据覆盖说明
```

缺少其中任何一类时：

- 缺进程执行：无法可靠证明未知文件运行。
- 缺文件事件：无法证明勒索加密或数据归集。
- 缺进程网络归属：无法可靠证明后门 C2 或数据外传由未知文件产生。
- 缺认证事件：无法还原账号和跨主机路径。
- 缺服务/持久化事件：无法证明后门持久化或勒索破坏恢复机制。
- 缺历史查询：无法完成跨时间分析。
- 缺统一主机身份和跨主机查询：无法完成跨主机分析。
- 缺覆盖说明：无法解释“没有发现”的可信度。
