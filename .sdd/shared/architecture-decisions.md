# Architecture Decisions

## AD-001：数据底座独立于研判引擎

**状态：接受。** 安全数据接入、规范化、存储、查询和数据权限由独立数据底座负责。研判引擎通过稳定查询契约访问数据，不自行建设日志平台。

## AD-002：LLM 与领域研判能力共同组成研判引擎

**状态：接受。** LLM 负责开放性理解、假设和调查规划；确定性工具负责关联计算；证据模型和 Validator 负责可信边界。领域能力不是独立的中间微服务。

## AD-003：研判与处置建议使用两个 LLM 循环

**状态：接受。** 两个循环通过 `JudgmentResult` 解耦。处置建议不得修改研判事实，实际执行必须经过策略和审批。

## AD-004：RAG 优先用于组织处置知识

**状态：接受。** 第一优先级是 SOP、审批、业务约束和回滚手册；第二优先级是调查方法和威胁知识；历史案件只能形成候选解释。原始安全遥测继续使用结构化查询。

## AD-005：设计文档按 Feature 归属

**状态：接受。** `.sdd` 根目录只保留导航和总体架构；每个 Feature 在 `features/` 下维护需求、设计、模型和验收；跨 Feature 内容进入 `shared/`。
