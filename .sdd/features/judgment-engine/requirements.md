# Judgment Engine Requirements

## 目标

从未知文件案件出发，动态查询证据，形成文件来源、执行、行为、影响、攻击路径和威胁性质的可追溯判断。

## 功能要求

- LLM 可以建立候选假设、选择调查方向、比较解释并生成案件说明。
- 所有案件事实必须来自数据底座返回的 Evidence 或确定性计算结果。
- 调查工具必须声明输入、输出、权限、成本和可解决的问题。
- 系统必须保存支持证据、反证、Coverage 和未解决问题。
- 场景至少覆盖文件来源、后门/C2、数据窃取、勒索和受控跨主机调查。
- 结案必须输出结构化 `JudgmentResult`，并允许明确返回证据不足。

## 安全要求

- LLM 不得创建虚构 Evidence、Fact 或 Finding。
- 查询不得超出案件身份和 Scope。
- 高置信恶意结论必须通过场景化证据门槛。
- RAG 结果只能指导调查或解释背景，不能作为当前案件行为证据。

## 验收条件

- 每个场景的恶意、良性和证据不足 Case 均有自动化回归。
- Verdict、Finding 和攻击路径边均可解析到存在的 Evidence。
- 更换 Planner 模型不改变确定性证据语义和最低结论门槛。
