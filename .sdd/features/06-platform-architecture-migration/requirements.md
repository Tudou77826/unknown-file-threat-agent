# Platform Architecture Migration Requirements

## 1. 目标

在保留当前研判能力和回归用例的前提下，将单进程调查原型迁移为具有以下边界的平台化应用：

- 数据底座提供规范化安全数据和 Coverage，不参与威胁判断；
- 研判与处置建议分别由独立 LLM 循环驱动；
- 为 RAG 预留独立契约和调用边界，本次不实现知识接入与检索；
- 展示层以稳定读模型呈现案件过程与结果；
- LangGraph 负责流程路由、状态检查点、暂停恢复和人工介入。

## 2. 必须满足

### 数据底座

- 通过稳定查询契约返回规范化 Evidence、Coverage 和来源引用。
- 查询必须显式携带租户、案件、Scope、时间范围和预算。
- 保留本地 JSONL/Fixture 作为开发适配器，业务流程不得依赖其文件结构。

### 双 LLM 循环

- 研判循环输出结构化 `JudgmentResult`，事实、发现和结论必须引用案件证据。
- 处置循环只读 `JudgmentResult`，输出结构化 `ResponsePlan`，不得改写研判事实。
- 两个循环具有独立提示、工具、状态、预算、结束条件和失败策略。
- 确定性 Analyzer、Policy 和 Validator 保留为可信约束，不交给 LLM 自由解释。

### RAG

- 只定义 `KnowledgeQuery`、`KnowledgeResult` 和 `KnowledgeRetrievalPort`。
- 两个 LLM 循环保留可选知识上下文输入，没有 RAG 实现时必须正常运行。
- 提供明确返回“能力未配置”的 Null Adapter，不加载文档、不生成 Embedding、不建立索引。
- RAG 的知识来源、分块、检索、ACL、引用和评测作为后续独立需求设计。

### LangGraph 流程

- 使用父图编排案件生命周期，研判与处置使用独立子图。
- 节点返回显式状态更新，不允许任意节点原地修改全部共享状态。
- Scope 扩展和处置审批使用可持久化中断，支持恢复、拒绝和超时结果。
- 外部查询、模型调用和处置动作具备幂等标识；失败后可从最近检查点恢复。

### 输出展示

- 提供与运行状态解耦的案件读模型，覆盖结论、证据链、Coverage、调查轨迹、处置建议、审批状态和限制。
- 首版提供只读案件视图；处置执行不属于本需求。
- 保留现有 JSON、Markdown 和命令行输出兼容入口。

## 3. 非目标

- 建设完整 SIEM/Data Lake 产品或替代现有安全设备。
- 在首版接通高风险自动处置。
- 实现 RAG 文档管线、Embedding、索引、检索或重排。
- 用向量检索查询原始进程、文件、网络等遥测。
- 在迁移过程中重写已经通过验证的场景规则和确定性 Analyzer。
- 一次性拆分为多个独立部署的微服务。

## 4. 验收条件

- 现有回归 Case 的研判语义不退化，原有测试全部通过。
- 同一案件可从检查点暂停并恢复，恢复后不重复已成功的外部副作用。
- 研判图和处置图可分别测试、替换模型并配置预算。
- 未授权的 Scope 扩展和处置方案不能越过人工中断节点。
- RAG 端口与 Evidence 查询端口类型隔离，Null Adapter 不影响双循环结束。
- 展示层只依赖稳定读模型，不直接读取 LangGraph 内部状态或本地 Case 文件。
- 本地开发环境无需外部数据湖和向量数据库即可运行完整演示。
