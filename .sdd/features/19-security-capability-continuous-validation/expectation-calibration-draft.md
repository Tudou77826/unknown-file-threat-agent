## 逐案例三步清单（已评测 5 例）

### c2-malicious-elf（手写基准，维持确认恶意）

- ① 事实：隐藏路径无包归属 ELF 由 SSH 会话 root 执行 → 固定间隔多次信标 →
  systemd 服务写入/启用 → 入站指令触发 root shell 执行命令并回传（手写剧本，行为链真实）
- ② AI 可见（16 事件）：执行(锚点) + 父链×3 + 网络×4 + socket 收发×2 +
  systemd 写入/启用×3 + 反证×2（包不归属、端点未批准）
- ③ 提案：**confirmed_malicious（维持）**。五类独立信号闭环（持续信标、持久化、
  命令交互、双反证），不属"三件事凑齐"的弱组合。

### c2-benign-baseline（手写基准，维持良性）

- ① 事实：厂商监控代理随 systemd 服务运行、回连批准端点
- ② AI 可见：包归属有效 + 端点批准 + 执行 + 服务事件
- ③ 提案：**benign（维持）**。

### t1105 工具传输（提案：倾向恶意；决策点 A）

- ① 事实（已修正）：file:// 本地协议复制落地（无外部网络传输）+ chmod + root 执行 +
  单次回连本机模拟端口 127.0.0.1:8443
- ② AI 可见（当前 4 事件）：执行(hash 锚点) + 网络×1 + 包不归属 + 端点未批准；
  补采后预期新增：文件写入事件
- ③ 提案：**likely_malicious**。依据：非包归属 + root 执行 + 落盘写入 + 外连四个独立
  信号，但无持久化、无重复外连、无命令交互，够不到确认级。
  **决策点 A**：本机回环端口的"未批准"反证本身偏弱（CMDB 批准清单不列回环地址属正常，
  工程师已点名清单不完备风险）——若按弱反证口径，应降为 **suspicious**。请裁决。

### t1053 cron / t1037 rc.local（提案：倾向恶意；决策点 B）

- ① 事实（已修正）：写入 /etc/cron.d 或追加 rc.local（周期执行/自启未实际发生，
  载荷为手动触发一次）+ 单次回连
- ② AI 可见（当前各 4 事件，文件写入丢失）：执行 + 网络×1 + 双反证；
  补采后预期新增：/etc/cron.d、/etc/rc.d/rc.local 的写入事件
- ③ 提案：**likely_malicious**（补采后证据成立时）。root 向系统持久化路径写入指向
  非包归属、外连未批准端点的 ELF，恶意性强但单次行为。
  **决策点 B**：若评审认为"持久化写入 + 指向载荷外连"已构成确认级闭环，可定
  **confirmed_malicious**——即工程师保留的"完整证据下应达到更明确判断"目标位。请裁决。
  不预设备齐后必然确认，以补采实际证据为准。
