# 安全能力持续仿真与 AI 研判评测 — Design

## 1. 总体架构

> 标准攻击 + 自主攻击 → Case 沉淀 → Replay → 规则检测 → AI 研判 → 自动评分 → 持续回归

```text
ATT&CK / 威胁情报 / 历史案例
             │
             ▼
        攻击测试体系
             │
      ┌──────┴────────┐
      ▼               ▼
标准攻击体系       AI自主攻击
Atomic/CALDERA    Pentest Agent
      │               │
      └──────┬────────┘
             ▼
       标准化 Test Case
             │
             ▼
        Replay Dataset
             │
             ▼
         被测安全系统
      ┌──────┴──────┐
      ▼             ▼
  确定性规则      未知文件
                     │
                     ▼
                  AI Agent
                     │
             研判 + 证据 + 建议
                     │
                     ▼
                   Scorer
                     │
                     ▼
             结果统计 / 回归趋势
```

## 2. 攻击数据来源

### 2.1 标准攻击

以 ATT&CK 作为统一坐标系，结合 Atomic Red Team、CALDERA 与 Adversary Emulation 构造固定剧本，承担两件事：验证规则在已知行为上的检出与 ATT&CK Technique 覆盖；以固定剧本和固定 Ground Truth 提供可重复的回归基线。

PoC 技术选择限定三条：Linux 平台可执行、攻击落文件产物（判定对象存在）、处于单主机调查边界内；优先选择落盘载荷本身恶意的技术。依据 ATT&CK v19.2 语料统计，Linux 可用 355 条技术中约 205 条具备文件类可观测，PoC 所需 10～20 条在该池内选取；不落文件的纯行为技术（约 150 条）不在 PoC 范围。

### 2.2 AI 自主攻击

自主渗透 Agent 只获得目标环境、授权边界、攻击目标和可用工具，自主完成侦察 → 规划 → 执行 → 观察 → 调整 → 继续。其数据价值在于攻击路径非固定，用于补充标准剧本覆盖不到的攻击序列。

## 3. Case 与 Replay 模型

### 3.1 Test Case

| 字段 | 含义 |
|---|---|
| case_id | Case 唯一标识 |
| attack_tags | ATT&CK Technique / Tactic 标签 |
| scenario | 攻击场景描述 |
| files / telemetry | 涉及的文件与相关 Telemetry |
| ground_truth | 期望判定（恶意 / 正常）及依据 |
| expected_rule | 预期规则检测结果 |
| expected_ai | 预期 AI 研判结论 |
| key_evidence | 关键证据 |
| risk_level | 风险等级 |
| recommended_action | 推荐处置 |

Case 支持参数化，同一剧本可派生多个变体。

PoC 阶段每个 Case 锚定一个判定对象文件（对齐现有 `cases/` 的 `input.json` 结构）；ground_truth 同时记录行为级依据（ATT&CK 技术是否达成）与文件级判定（该文件是否恶意），以覆盖良性文件被滥用类场景。

### 3.2 Replay Dataset

首次真实攻击运行后保存文件、日志、网络、进程、告警与上下文，形成可重放数据集，使研发回归无需重复发动攻击。Replay 的文件与遥测字段对齐 Feature 01 的数据模型，保证 Replay 可直接进入被测链路；现有 `cases/` 的 `input.json` 与 `events/` 结构作为首批基线。

原则：**Replay 做 AI 侧高频回归，真实攻击做周期性端到端验证并承载规则侧检出评测。**

## 4. 被测链路与结果采集

测试数据进入被测安全系统后：

```text
测试 Case
   ↓
确定性检测规则
   │
   ├─ 命中 → 已知威胁告警
   │
   └─ 未命中
        ↓
      未知文件
        ↓
      AI Agent
        ↓
研判结论 + 证据 + 风险 + 处置建议
```

规则侧由外部态势感知系统承担：在受其防护的目标环境上真实执行攻击，检测在攻击运行期自然发生；采集适配器从态势感知系统读取命中 / 未命中与告警，收敛为统一的规则结果记录，不改造其检测行为，也不建设向其回放数据的注入通道。规则侧每个 Case 需采集受理回执：已受理且处理完成但无告警，方可计为漏检；未受理不计入结果。

采集侧只读取两类记录：规则侧为命中 / 未命中与告警内容，AI 侧为研判结论、证据、风险与处置建议。采集不改变两侧系统行为。

## 5. 评分体系

### 5.1 规则能力

检出率、漏检率、误报率、ATT&CK Coverage、历史 Case Regression。误报率基于与恶意 Case 同 schema、同采集管道的良性基线集计算。

### 5.2 AI 能力

规则漏检后的 AI 补漏率、恶意 / 正常判断正确率、证据分析正确率、风险等级正确率、处置建议正确率、多次运行稳定性、研判耗时与成本。

核心指标：

> AI 补漏率 = AI 正确识别的规则漏检恶意样本 / 所有规则漏检恶意样本

### 5.3 整体能力

> 规则覆盖 + AI 增量覆盖 = 整体有效感知覆盖

规则漏检后暴露的未知文件规模，由规则指标与整体覆盖之差刻画。

## 6. 与既有能力的关系与复用边界

AI 侧的评测执行复用 Feature 16 的三件套与两段式：Case 作为 Dataset 单元、Replay 运行作为执行段、Scorer 作为打分段。本 Feature 只补充攻击侧（Case 生产与 Replay 管理）与规则侧（规则结果采集与规则评分器），不重复实现调度、并发与产物落盘。

ATT&CK 标签与 T-ID 通道复用 Feature 18 的语料。被测 AI 链路为 Feature 02 / 03 的研判与处置建议，本 Feature 不改动其行为。规则侧为外部态势感知系统，本系统只采集其检测结果，同样不改动其行为。本 Feature 的 Test Case 不是案件治理的 InitialCase，不复用案件身份、Scope 与生命周期。

## 7. OpenAEV 集成边界

OpenAEV 提供 Scenario / Campaign 管理、Simulation 调度、攻击执行管理、Case 生命周期、周期测试与历史趋势；本系统在其上补齐 Case 标准化、Replay 管理、规则与 AI 结果采集和自有 Scorer。

边界：OpenAEV 管测试，自有 Scorer 管评分，两者通过 Case 与运行结果交换。

## 8. 运行模式

| 模式 | 触发 | 输入 | 目的 |
|---|---|---|---|
| 固定回归 | 版本变更 | Replay Dataset | 高频验证 AI 侧模型、Prompt、RAG、Agent 版本 |
| 周期实测 | 周期调起 | Atomic / CALDERA / 完整攻击链 | 端到端验证真实链路 |
| 自主探索 | 周期调起 | AI Pentest Agent | 探索新路径，产出 Candidate Case |

Candidate Case 需人工确认后进入正式回归集。

## 9. 风险与边界

- 自主攻击可控性：AI 自主攻击只在有明确授权边界的靶场内运行；本系统不承担自动阻断。
- Ground Truth 维护：Case 与其 Ground Truth 是评测可信度的前提，变更需版本化并复核。
- 环境漂移：Replay 产物依赖被测环境版本，环境变化需重新采集而非沿用旧产物。
- 外部依赖：规则侧结果依赖态势感知系统的部署、接口与告警格式，差异与不可用在采集适配器内收敛，不反向改造其行为。
- 指标可比性：跨版本回归要求 Scorer 与 Case 版本钉住，否则趋势不可比。
