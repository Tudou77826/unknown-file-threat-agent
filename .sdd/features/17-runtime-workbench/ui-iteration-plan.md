# 运行工作台 · 全量优化迭代计划

定位校准（产品北极星）：**事件进 → 一键发起排查 → 实时可交互地看着它逐步工作 → 关键点接手**。
像主流 coding agent / chat agent 一样提供实时反馈与交互式处理流程；管理面（审计/知识/案件）保留但降为次要导航。

现状差距：工作台首屏是"运行结果视角"（运行列表），缺**输入面**（种子事件浏览 + 可访问数据浏览）与**进行中调查的第一视角**（实时流 + 内联交互）。

---

## 迭代 0 · 体验底座（半天~1 天，前端）

一切后续迭代的地基，消除"demo 感"的交互硬伤（三方评审 P0 集中区）：

1. `toast()` 轻提示 + 应用内确认 Modal（替换全部原生 confirm/alert，说明后果）；
2. `safeFetch()` 统一封装：loading 骨架 / 错误重试条 / 空态设计；
3. 自动刷新可暂停 + "更新于 x 秒前"；
4. 枚举中文化映射表（status/stage/publication_status/approval_class/audit 动作）+ 相对时间（悬停显示绝对时间）；
5. 正确性硬伤：suspicious 判定配色（黄，非绿）、`.metric` 类补定义、token 格式化（↑in ↓out）、report_id 深链、失败横幅带 error_message 与失败事件锚点。

验收：三方评审中标注"不专业感"的交互条目全部消除；无原生弹窗残留。

## 迭代 1 · 输入面：种子事件与数据浏览（1.5~2 天，新页面 + 3 个 API）

**北极星的前半句。当前完全缺失，是新的第一屏。**

1. **种子事件列表页**（新导航首屏，置于"运行工作台"之前）：
   - 事件 = 预置数据集案件 + 已提交告警（alert_payload 工件）统一呈现；
   - 列：事件 ID、来源（EDR/SIEM/手工提交）、主机、文件摘要、检出时间、**数据完整度指示**（L0~L3 或可回答问题数）、是否已建案；
   - 筛选：来源/主机/已建案状态。
2. **事件详情页**：
   - 原始告警载荷（格式化 JSON，字段中英对照）；
   - **可访问数据一览**：按域（进程/网络/文件/服务/软件包/资产基线）显示记录数、时间范围、样例 3 条、覆盖度——"我们能拿到的证据"在发起前可见；
   - 主操作：`发起排查`（选择档位，默认推荐档）。
3. **数据浏览器**（独立页，或事件详情内嵌 Tab）：
   - 按数据源浏览活动库：域 → 字段字典 → 样例记录（复用 data_foundation 查询适配器，只读）。
4. 新 API：`GET /api/events`（种子事件聚合）、`GET /api/events/{id}`（载荷+数据源概览）、`GET /api/data/sources`（各域统计与样例）。

验收：从"看到事件"到"发起排查"≤ 2 次点击；发起前能回答"这个事件我们有哪些数据可用"。

## 迭代 2 · 进行中调查的实时交互面（2~3 天，核心体验重构）

**北极星的后半句。像 coding agent 一样"看着它工作"。**

1. **调查运行页 = 第一视角直播**（替代当前"事后轨迹页"承担进行时职责）：
   - 顶部阶段条：intake → 调查循环（当前节点高亮脉动）→ 报告 → 审批 → 处置，SSE 驱动；
   - 活动流：SSE 逐事件流入，按轮分组（当前轮次卡置顶展开），工具调用显示 参数→结果 折叠对；
   - 实时累计：已用轮次/工具调用/token/耗时（引擎侧 usage 回写后自动生效）。
2. **关键点内联交互**（不离开直播页）：
   - 审批中断 → 页面内弹出审批卡（四态决策，编辑计划带 diff 预览），决策后流程原地继续；
   - 预算耗尽/降级/边界拒绝 → 内联说明卡（不再只进事件流）。
3. **完成时原地展开**：研判报告 + 处置方案在直播流尾部展开渲染（结论徽章/关键证据/引用回溯），不跳页。
4. 调试恢复改异步：202 + 进度显示（SSE 复用），重放事件独立泳道徽章。

验收：发起排查后停留在一页看完全过程；审批不跳页；失败时当屏看到根因事件。

## 迭代 3 · 引擎侧可观测补全（2~3 天，含引擎改动）

1. 调查循环**每次模型调用**发 model_input/output 事件（当前仅报告/处置阶段有）——失败定位与 prompt 复盘的数据基础；
2. token usage 从 LLM 响应回写事件 → 轮次/阶段/运行三级聚合 → KPI 与瀑布图生效；
3. 轨迹页 trace 瀑布：按 `duration_ms`（数据已存在未渲染）画每跳时延横条，按 node 分组成树；
4. debug 事件泳道 + checkpoint 恢复前预览（state 摘要 + 将重放节点清单）；state_summary 暴露为 API；
5. 边界拒绝聚合面板（"模型反复撞墙"是 prompt 质量的最强信号）。

验收：失败运行可在当屏回答"哪次调用、发了什么、为何被拒、花了多少"。

## 迭代 4 · 三方评审修复清单清账（1~2 天）

- 快修档全清：run 对比视图（运行表多选 → 并排 verdict/轮次/token/证据差异）、审计分页+搜索、report_id 深链、知识页"配置已生效但历史运行未命中"矛盾提示、投毒测试语料加"测试样本"徽章、驳回/忽略语义说明、recommended 方案无审批入口的解释、`/cases/{id}` 孤页并入设计系统、演示剧本入口收敛；
- 引擎侧：token/成本视图、工具降采样上下文核查（恶意样本失败疑因）。

## 迭代 5 · 管理面完善与产品化（按需，次要）

案件档案增强（结论演进对比）、报告/审计导出（PDF/CSV）、告警批量导入、Dashboard 总览页（趋势 KPI）、设置页（模型/知识/预算可视化）；**另立项**：身份/RBAC、SIEM 连接器、Prompt 管理与版本对比、评测基线（等 Feature 16）。

---

## 依赖与风险

- 迭代 2/3 有引擎侧改动（调用级事件、usage 回写）——遵循"平台不新增业务层"，事件经既有 emit 通道，架构测试照常约束；
- 迭代 1 的"可访问数据一览"依赖真实数据源接入程度：预置数据集完整可演示，真实遥测接入属 Feature 01 范围，页面按"已接入/未接入"如实标注；
- 全程自包含 UI（无 CDN），保持内网可用。
