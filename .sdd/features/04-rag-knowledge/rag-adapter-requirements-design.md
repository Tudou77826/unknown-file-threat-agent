# 安全知识能力与 RAG 适配层需求设计

## 1. 状态与目标

状态：目标需求设计，尚未实施真实 RAG 接入。

本能力为未知文件研判和处置建议提供可追溯的外部知识增强，辅助 AI 在两处
决策点做出更高质量的判断，同时保持 Agent、研判逻辑和处置逻辑不依赖任何
具体 RAG 团队、产品或检索技术。

核心决策是：**安全知识能力层决定“查什么”，RAG 适配层决定“怎么查”。**
Agent 只表达当前安全业务场景和已知上下文，不感知知识库名称、集合、
向量、召回数量、重排序、混合检索或供应方协议。

## 2. 适用范围

首期只支持两类面向 Agent 的知识能力，接入以下知识来源：

| 业务场景 | 知识用途 | 首期知识来源 | 使用边界 |
|---|---|---|---|
| 未知文件研判 | 辅助解释行为与遥测、形成调查假设和选择下一步验证方向 | 人工研判经验、ATT&CK 知识、告警/日志含义手册 | 只能作为调查指引和遥测语义解释，不能成为当前案件事实或 Verdict 证据 |
| 处置建议 | 辅助选择可执行、可回滚且符合组织约束的动作 | 组织 SOP、审批与回滚手册、人工处置经验 | 仍须经过资产条件校验、处置策略和审批流程 |

其中告警/日志含义手册与同场景另两类来源性质不同：人工研判经验和
ATT&CK 属于外部经验知识，告警/日志含义手册用于解释当前遥测自身的
语义，两者的查询构造方式见第 6 节。

不在本期范围内：自建知识库、文档解析和导入、Embedding 或索引选型、
供应方选型、知识管理页面、相似历史案例检索（case_memory 域），以及
让 Agent 直接管理检索参数或知识内容。case_memory 域仍保留在
Feature 04 的知识域模型中，其编排约束作为后续接入的前置条件记录在
第 6 节。首期不启用它还有一层考虑：历史案件包含本系统自身产出的
研判与处置结论，让模型持续消费自己的历史输出来影响当前判断，容易
形成自我强化的偏移；后续接入前须先建立人工校准与抽样评测机制。

## 3. 目标边界

~~~mermaid
flowchart LR
    A[Security Agent] --> K[安全知识能力层<br/>业务场景与检索编排]
    K --> R[RAG 适配层<br/>协议、能力与结果归一]
    R --> P[第三方 RAG / 搜索 / Knowledge Agent]

    M[知识管理面] --> K
    M --> R
    M -. 导入与重建驱动 .-> P

    S1[人工研判经验] --> P
    S2[ATT&CK 知识] --> P
    S3[告警/日志含义手册] --> P
    S4[组织 SOP 与回滚手册] --> P
    S5[人工处置经验] --> P
~~~

| 层次 | 应负责的事 | 不应负责的事 |
|---|---|---|
| Agent | 表达研判或处置场景，提交脱敏后的案件上下文，消费带引用的知识 | 知道知识源、供应方、检索算法或参数 |
| 安全知识能力层 | 根据业务场景决定检索哪些知识、如何形成业务查询、如何按源合并结果与隔离失败、如何限制知识用途 | 处理供应方 SDK、鉴权协议、集合 ID 或重排序实现 |
| RAG 适配层 | 供应方路由、请求/响应转换、能力识别、超时、鉴权、错误归一和知识条目标准化 | 决定未知文件应查哪些知识，或用知识替代安全遥测 |
| 知识管理面（本系统） | 知识源映射、知识库配置、召回与重排序策略、导入与生命周期管理，经适配层驱动供应方引擎 | 被 Agent 在一次调查中直接调用 |

当前的 `KnowledgeRetrievalPort` 与 Null Adapter 是迁移占位契约。目标实现中，
它应位于安全知识能力层之下，成为适配层的内部依赖；它不是 Agent 的最终
业务接口。Agent 对知识的调用指向能力层的场景服务接口（接口形态见第 5 节），
而不是任何检索形状的接口——“依赖抽象、不依赖具体实现”中的那个抽象，
指的是业务场景契约；适配层与检索 Port 是能力层背后的实现细节，对 Agent
不可见。具体契约差距与调用点迁移见第 5 节。

## 4. 稳定的业务输入与输出

### 4.1 输入语义

面向 Agent 的请求只需要表达：

- 当前业务场景；
- 查询意图，例如需要调查指引、解释告警或日志含义、获取处置政策参考；
- 经最小化处理的安全上下文，例如已验证行为、待验证假设、待解释的告警或日志字段标识、研判结论、资产约束。

授权信息（租户、案件、调用身份）不由 Agent 声明，由框架的执行上下文
自动绑定并全程继承（见第 7 节授权继承）：知识按租户与 ACL 隔离，供应方
检索必须以调用身份进行；审计需要回答“谁在哪个案件查了什么”。Agent 可
填写的字段中不含授权类信息。

请求不得携带知识库 ID、collection、embedding、top K、过滤 DSL、重排序器
名称或供应方特有参数。这些配置只能由知识管理/运维面维护。

### 4.2 输出语义

返回值统一为标准化的知识条目（带引用），而不是供应方的 document、chunk、
node 或 hit。每条结果至少应表达：

- 稳定知识标识、版本和可定位片段。凭标识加版本可事后追溯；供应方元数据中若含状态或备注类信息，原样保留，本系统不建模引用状态；
- 知识来源类别、标题、内容摘要和适用限制。适用限制分两级：类别级限制由能力层按来源类别统一附加，始终存在，不依赖供应方（如“仅作调查指引”“须过审批与资产校验”“动作执行仍须满足组织政策校验”）；条目级限制来自知识自身元数据，允许为空；
- 归一后的排序与相关性等级；
- 可审计的来源定位和访问结果；
- 未配置、无结果、权限拒绝、超时或降级时的明确状态与限制说明。

供应方原始分数只能用于诊断和审计，不能作为跨供应方的业务判断依据。

## 5. 与现有占位契约的差距与迁移

当前代码中的 `KnowledgeQuery`、`KnowledgeResult`、`KnowledgeCitation` 与
Null Adapter 是占位实现。按第 4 节的目标语义，实施时需一并完成以下扩展。

请求侧差距：

- 增加查询意图字段（调查指引、告警/日志含义解释、处置政策参考）；
- 由单一自由文本查询扩展为结构化的最小化上下文（已验证行为、待验证假设、待解释的告警/日志字段标识、资产约束）；面向供应方的查询文本只是能力层生成的中间产物，不进入业务契约。

响应侧差距：

- 结果状态在现有 `available`、`empty`、`not_configured`、`error` 之外，增加可区分的 `permission_denied`、`timeout`、`degraded`；
- 每条引用增加知识来源类别、归一化相关性等级和适用限制（类别级始终存在，条目级可选），作为 RK-02 与 RK-05 的验收载体；
- 引用定位统一为 knowledge-model.md 定义的 `knowledge_id + version + chunk_id`（与现有 `document_id` 命名不一致）。

接口形态与调用点迁移：

- 能力层对上暴露两个场景服务，共用第 4 节输入/输出语义。
- 研判侧接入分两层：证据包组装完成、进入研判前，由固定节点执行一次基线检索（人工研判经验 + ATT&CK，用已验证行为构造查询）；另注册三个按用途拆分的工具——查询 ATT&CK 技术、解释告警/日志字段、查询研判经验——由模型在调查中按需调用。拆分的目的是提高触发率：通用工具要求模型先想到“查知识”，拆开的工具名直接对应调查中的具体需求。三个工具是同一场景服务的不同入口，参数仍是业务语义（行为描述、字段标识等），拆分不改变第 4 节契约。
- 处置知识由处置子图在固定编排节点中调用，时机固定在生成处置建议前。
- 研判结束处记录知识咨询情况（基线检索结果、各工具是否调用及返回状态），只记录不阻断。
- 所有工具的 Schema 与请求只含业务字段，不含任何检索参数，这是 RK-01 与 RK-04 的落点。
- 研判循环当前没有任何知识接入点，需新增基线检索节点与上述三个工具；处置子图当前直接调用 `KnowledgeRetrievalPort`，需改为调用能力层场景服务，Port 随之下沉为适配层内部依赖。
- Null Adapter 保留为未配置部署下的默认实现，其 `not_configured` 语义不变。

## 6. 场景编排与供应方适配

安全知识能力层按场景形成检索计划：

1. 未知文件研判在证据包组装后执行基线检索：并行检索人工研判经验和 ATT&CK 知识，查询由已验证行为构造；调查过程中，模型通过按需工具补充查询（ATT&CK 映射、告警/日志含义解释、研判经验）。所有结果分别保留来源类别和适用限制，再合并为调查指引。
2. 告警/日志含义解读通过“解释告警/日志字段”工具进行：查询由字段名、告警类型或日志标识直接构造，不依赖案件叙事；其结果只用于正确解读遥测语义，不改变遥测在证据模型中的地位。
3. 处置建议并行检索组织政策（SOP、审批与回滚手册）与人工处置经验。所有合格结果全部进入合并，不因来源不同丢弃、降权或隐藏；每条结果如实标注来源类别，排序只依据相关性，不依据来源级别。多种依据内容不一致时并列呈现，说明存在多种可参考依据，推荐由处置建议生成时给出并附理由，能力层不预先取舍；两份同级政策相互冲突时同样并列呈现并标注冲突，要求人工确认。信息的呈现方式不改变最终约束：处置动作仍须通过资产条件校验、处置策略与审批流程。
4. 相似历史案例（case_memory 域）不在首期。后续接入时只能提供候选解释或经验，不得复制为当前案件的 Fact、Finding 或 Verdict。
5. 多知识源并行时按源隔离失败：单一来源超时、权限拒绝或能力不足不拖垮其余来源；聚合结果按源保留状态与限制说明，整体降级必须显式标注，不得伪装成“没有相关知识”。

适配层接收内部检索计划后，才将其映射到供应方所需的请求形式。不同供应方可支持
语义检索、关键词检索、过滤、重排序、引用或访问控制中的不同组合。能力差异应由
配置和降级策略处理，不得迫使 Agent Prompt、Tool Schema 或工作流随供应方改变。

## 7. 安全、可信与韧性要求

- **授权继承**：调用身份、租户和知识源 ACL 由框架统一的执行上下文承载，在调用链上一次绑定、全程继承；严禁作为参数在各层之间手工传递，业务代码不得填写或篡改授权字段。未授权内容不得进入模型上下文或审计明文。
- **最小化外发**：对外部供应方只发送完成该检索所需的脱敏或分类后上下文；原始文件内容、密钥和不必要遥测不得默认外发。
- **内容不可信**：检索结果中的指令、命令和提示视为数据，不能改变系统 Prompt、工具边界、研判策略或处置审批规则。
- **可追溯**：记录场景、知识来源、版本/片段引用、策略结果、供应方标识与降级原因；敏感内容本身按最小暴露原则审计。审计记录接入案件治理的既有留痕通道，供应方调用明细留在适配层并通过 query_id 关联，不另建孤立日志。
- **可降级**：知识检索不可用、超时或能力不足时，系统应返回明确限制并继续基于安全遥测完成研判或处置流程；不得把失败伪装成“没有相关知识”。
- **事实隔离**：RAG 不返回当前案件的安全事实，且不能绕过已有的证据接地、报告校验、处置策略或人工审批。

## 8. 管理面与运行面分离

运行面仅提供上述两类安全知识能力。以下事项属于知识管理面，由本系统提供入口并驱动执行；RAG 供应方的定位是知识引擎，只提供被调用的引擎能力（检索执行，以及导入、索引重建等管理类接口），导入、调参、重建与查询均由本系统驱动。管理面操作同样经适配层作用于供应方，不直连供应方协议；以上事项均不得进入 Agent 调用参数：

- 知识源、知识库和租户映射；
- 文档导入、更新、撤回、版本和有效期；
- 召回数量、过滤策略、混合检索、重排序、阈值和超时；
- 供应方端点、凭据、能力声明、健康检查和切换策略；
- 质量评测、反馈闭环和索引重建。

首期只交付运行面；管理面（导入、调参、评测、重建的入口与驱动逻辑）属于
本系统的后续实施需求，不等待供应方提供管理能力——管理动作的执行方始终是
本系统，供应方只承接引擎侧调用。

## 9. 验收条件

| 编号 | 可检查结果 |
|---|---|
| RK-01 | Agent 只按“未知文件研判”或“处置建议”请求知识；请求契约与工具 Schema 中不出现供应方、检索参数或授权类字段，授权上下文由框架统一承载。 |
| RK-02 | 证据包组装后基线检索必定执行（不可用时显式降级标注，不阻断流程）；人工研判经验、ATT&CK 指引、告警/日志含义解释三类知识均可经对应入口取得，三类引用可区分与追溯。 |
| RK-03 | 处置知识检索结果全部如实呈现：政策与经验分别标注来源、可追溯，多种依据并列不丢弃，推荐至多附带理由；最终处置动作仍满足审批、回滚与资产适用条件。 |
| RK-04 | 更换或新增供应方时，不修改 Agent Prompt、Tool Schema、案件工作流或业务场景契约。 |
| RK-05 | 所有返回结果具备稳定引用、版本/片段定位、来源和限制；供应方原始分数不进入业务判断。 |
| RK-06 | ACL、租户、密级和有效期过滤在模型可见前完成；提示注入型知识内容不能改变系统边界。 |
| RK-07 | 未配置、权限拒绝、超时和能力降级均有可区分状态，多源并行中单源失败时其余来源结果仍可用，且任何知识失败不阻断基于安全遥测的核心流程。 |
| RK-08 | 导入、调参与供应方切换只能经管理面配置完成（首期以配置文件或配置项承载，管理界面为后续需求），Agent 不能在运行中修改这些设置。 |
| RK-09 | 本期交付包含一个行为可控的参考适配器（内存固定语料，可模拟全部可区分状态与降级路径），RK-02 至 RK-07 的验收在该适配器上执行；真实供应方接入另立实施需求。 |

## 10. 与现有设计的关系

本设计细化 Feature 04 已定义的知识域、ACL、版本、引用和检索安全约束，并与
Feature 02 的“知识不能替代案件证据”、Feature 03 的处置策略校验保持一致。
告警/日志含义手册对应 Feature 04 知识域模型中 Investigation 域的“数据字段
说明”。对 Feature 04 已有规则有两处收窄，实施和后续修订时以本设计为准：
其一，处置场景不再按“政策优先于经验”合并，改为全部并列呈现、按相关性
排序，取舍交给处置建议生成与人工确认；其二，不在本系统内建模引用的撤回
或替代状态，凭 knowledge_id 加版本事后追溯。真实供应方接入、管理面实现
和知识质量评测应在本设计验收后作为独立实施需求，不得因已有 Null Adapter
而被误认为已经交付。
