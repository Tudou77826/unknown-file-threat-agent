# Data Exfiltration Scenario

## 需要回答

- 进程树是否成功读取敏感数据？
- 是否把敏感输入关联到具体归档或暂存对象？
- 该对象是否通过 HTTPS、其他网络传输或 DNS 发送？
- 进程、数据对象、端点和时间顺序是否一致？
- 是否命中批准的备份、同步或传输基线？

## 结论门槛

发现命令、敏感路径提及、归档创建、高出站流量或编码 DNS 均不能单独证明窃密。confirmed malicious 需要敏感读取、数据暂存、明确外传和反证检查形成同一归因链。

## 反证

批准的进程、目标端点、变更窗口和数据范围共同满足时，可以形成合法备份或同步解释。
